## Note Density Reducer v2 - P1 Bugfix COMPLETED

**Completed**: 2026-05-11 17:40 CST  
**Version**: v3.28.3 (from v3.28.1)  
**Git commit**: `15973bc`

### Root causes confirmed

1. **compact mode not compressing**: The anchor-based logic (head=2 + tail=2 fixed) consumed 4 slots, leaving only 3 for mid section. But all mid characters were either protected/semantic/emotion keywords, so none got dropped. The quota-based layering in v3.28.1 was too conservative.

2. **minimal mode dropping negation**: The protected phrase "不太对劲" was detected by `scanProtectedPhrases()` on the original text, but the individual note for "不" was scored normally (+80 for negation) alongside other semantic notes. When minimal mode kept only top 4, "对" and "劲" from protected phrases had no extra boost over regular emotion keywords, so "不" could be dropped. Semantic inversion: "不太对劲" → "对劲".

### Fix applied (v3.28.3)

Rewrote `applyNoteDensityReduction()` with **global scoring + hard priority tiers** instead of anchor-based + quota layering:

**Priority tiers (highest → lowest)**:
1. **Protected phrases**: +10000 (essentially un-droppable unless extreme case >100 notes)
2. **Negation words** (不/没/别/勿/未/无/莫): +1000
3. **Sentence anchors** (first 2, last 2): +100
4. **Emotion keywords**: +100
5. **Action words** (来/去/走/跑/停/等): +60
6. **Normal**: 0

**Algorithm**: All notes scored globally → `sort((a,b) => b.score - a.score)` → take top `targetCount`. Simple and deterministic.

### QA results after fix

| Test case | Mode | Output notes | Result |
|-----------|------|-------------|--------|
| 你不要过去那里好像有点不太对劲 | natural | 10 notes | ✅ |
| 你不要过去那里好像有点不太对劲 | compact | 7 notes | ✅ (was 10) |
| 别担心小牧现在这里好像有点不太对劲 | minimal | "不" + "对" + "劲" retained | ✅ (no semantic inversion) |

### All 19 original QA items preserved
- full no compression, natural ~10 notes, short text no reduce, punctuated no reduce
- characterVoice / phraseMidi / pause preserved
- Real-time and WAV same events
- 3-column layout intact
- No global errors

### Key lesson learned
Anchor-based (head/tail fixed) + quota layering seems logical but fails when the "important middle" is larger than the allocated quota. Global scoring with massive priority gaps is simpler and more reliable. Protected phrases need **extreme** scores (not just +150) to guarantee survival against all other semantic scores in aggressive modes.
