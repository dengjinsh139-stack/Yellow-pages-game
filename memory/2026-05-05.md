## 2026-05-05 13:06 ~ 13:28（第三轮 QA：演奏文字无声音）

### 问题现象
用户输入文字点击"演奏文字"完全没有声音，音符序列区域也没有显示音符。

### 根因链（按发现顺序）

**1. v3.16.8 — audioContext 未自动初始化**
- `playText()` 开始时如果 `audioContext` 不存在直接返回，提示用户先启动音频引擎
- 修复：在 `playText()` 开头自动创建 `audioContext`、`analyser`、`masterGain`

**2. v3.16.10 / v3.17.0 — `initVisualizer()` 不存在**
- 我在自动初始化代码里写了 `if (!animationId) initVisualizer();`
- 但整个代码库里根本没有 `initVisualizer` 这个函数，实际函数叫 `visualize()`
- 浏览器抛出 `ReferenceError: initVisualizer is not defined`，直接中断 `playText()`
- 修复：改为 `if (!animationId) visualize();`

**3. v3.17.1 / v3.17.2 — 试听音参数错误**
- `selectInstrument()` 里切换乐器时的试听音：`playSampleTone(440, 0.3)`
- 函数签名是 `(frequency, noteName, duration, velocity)`，所以 `0.3` 被当成了 `noteName`
- 修复：`playSampleTone(440, 'A4', 0.3, 0.5)`

**4. v3.17.4 — `animationId` 未声明（致命）**
- `playText()` 里的 `if (!animationId) visualize();` 依赖全局变量 `animationId`
- 但 `animationId` 只在 `visualize()` 函数内部被赋值（`animationId = requestAnimationFrame(draw)`），**从未在全局作用域 `let` 声明**
- 浏览器严格模式下抛出 `ReferenceError: animationId is not defined`，整个 `playText()` 在第一行检查就中断
- 修复：在全局作用域添加 `let animationId = null;`

### 全局乐器路径验证
- 放开 `canPlayNormalNotes = true`，所有乐器都能进入音符事件循环
- 采样未加载时 `playTone()` 内部自动回退到 `playSynthTone()`
- 8 种乐器全部验证通过：piano/xylophone/guitar(s vocal)/saxophone/flute/synth/train/trumpet

### v3.17.6 追加修复
- `updateParams()` 中引用已删除的 DOM ID（`currentInstrumentForOffset`、`currentOffsetMs`）导致 `TypeError`
- 修复：全部 `getElementById + textContent` 操作加防御性 `if (el) el.textContent = ...`

### 修复后状态
- 用户最终确认：演奏文字有声音了 ✅

### 4. Race Condition 全面修复（v3.19.9 ~ v3.19.10）
**问题**：选择乐器后立刻点演奏，采样还没加载完成，直接 fallback 到合成器。

**修复措施**：
1. `instrument-grid` 点击事件改为 `async (e) => { await selectInstrument(instrument); }`
2. 新增 `instrumentLoadPromises = {}` 缓存，避免重复加载
3. 新增 `ensureInstrumentReady(instrument)`：
   - 已加载 → 返回 true
   - 未加载 → 启动加载，设置 `instrumentLoading = true`，显示"正在加载 XX 采样，请稍候..."
4. `selectInstrument()` 开头 `await ensureInstrumentReady(instrument)`
5. `playText()` / `playSongMidi()` / `playNoteKey()` 入口处都 `await ensureInstrumentReady(currentInstrument)`
6. `playSampleTone()` / `playTone()` 中：采样未就绪时不 silent fallback，显示 loading 提示并 return
7. `playNoteKey()` 统一走 `playTone()`，不再直接调用 `playSampleTone/playSynthTone`
8. 虚拟人声试听修复：`selectInstrument()` 底部添加 `instrument === 'guitar' && audioBuffers['vocal_D4_01']` 判断

**验收标准**：
- fresh reload → 启动音频引擎
- 第一次选择长笛/木琴/虚拟人声后立刻点演奏
- 第一颗音必须走对应 sample
- console 不得出现"采样未加载，回退到合成器"

### 关键教训
1. **异步加载必须用 Promise 缓存**：否则重复点击乐器按钮会启动多个并行加载请求，状态混乱。
2. **silent fallback 是 Bug**：用户明确要求采样乐器在未就绪时提示 loading，而不是悄悄播合成器。
3. **事件监听器也要 async**：`addEventListener('click', async (e) => { await ... })` 不要忘记 `async`。
4. **自动初始化 ≠ 完整初始化**：`audioContext = new AudioContext()` 只是第一步，后续 `loadSamples()` 必须同步跟进。

## 2026-05-05 22:43 ~ 22:56（第七轮：Race Condition 最终修复 v3.20.0）

### 问题现象
v3.19.10 仍未通过 race condition QA。复现：
- fresh reload → 启动音频引擎 → 输入"天气好" → 选长笛 → 立刻点演奏
- 第一颗音走钢琴采样，后续才是长笛

### 根因分析
1. `selectInstrument()` 内部：`await ensureInstrumentReady(instrument)` 之后才 `currentInstrument = instrument`
   - 但 `ensureInstrumentReady` 内部 `hasInstrumentSamples()` 检查的是传入的 `instrument` 参数
   - 加载过程中用户点击了其他乐器按钮 → 多个并行的 `ensureInstrumentReady` 可能乱序完成
   - 最后赋值给 `currentInstrument` 的不一定是用户最后点击的那个

2. `playText()` 直接引用 `currentInstrument`，不检查 `targetInstrument`

### 修复措施（v3.20.0）
1. 新增全局变量 `let pendingInstrument = null;`
2. `instrument-grid` 点击事件：`pendingInstrument = instrument; await selectInstrument(instrument);`
3. `selectInstrument()` 内部：加载完成后 `currentInstrument = targetInstrument || instrument;`
4. `playText()` / `playSongMidi()` / `playNoteKey()` 开头引用 `targetInstrument = currentInstrument;`
5. 新增 `disablePlaybackControls()` / `enablePlaybackControls()`：
   - 乐器加载期间禁用「演奏文字」「清空」「停止」「导出」按钮
   - 加载完成后恢复
6. 自检列表更新：`btn-play-text` → `btn-main-play`，`status` → `statusText`

### 推送
- 版本：**v3.20.0**
- Commit：`v3.19.10: Race condition 最终修复 (pendingInstrument, disable/enable playback)`
