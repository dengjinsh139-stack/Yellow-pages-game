### 上午后续 (11:24-11:48) - 音量均衡问题排查

#### 问题发现
用户反馈音符键盘音量不一致（B4到B5音量递减）。

#### 根本原因
1. **A5.wav 文件丢失** - 未从 inbound 目录复制
2. **原始WAV采样本身响度不同** - 通过Python测量RMS发现：
   - F5: RMS=512.9 (基准，最响)
   - A5: RMS=319.1 (只有F5的62%！)
   - D5: RMS=378.6 (只有F5的74%)
   - B4: RMS=398.9 (只有F5的78%)

#### 解决方案
1. 恢复丢失的 A5.wav 文件
2. 为每个采样计算基于实际RMS的精确增益补偿：
   ```
   D4: 1.077, E4: 1.029, F4: 1.027, A4: 1.013, B4: 1.286
   D5: 1.355, E5: 1.043, F5: 1.000, A5: 1.608, B5: 1.240
   ```
3. 在 sampleConfig 中为每个采样添加 gain 属性
4. 播放时应用补偿：`velocity * baseGain * highFreqCompensation`

#### 关键代码变更
- 添加 A5.wav 到采样目录
- 修改 sampleConfig.piano.samples 结构，增加 gain 字段
- 更新 playSampleTone 函数使用精确增益补偿

#### 版本号规则确认
- 两位数进位：3.3.16 → 3.4.0

#### Bug: 音符键盘无声音
**现象**: 点击音符键盘没有声音

**排查过程**:
1. 浏览器测试发现 `samplesLoaded=true` 但 `audioBuffers` 为空
2. 控制台无JavaScript错误
3. 发现 `playSampleTone` 函数调用失败
4. 最终定位到变量名冲突问题

**根本原因**: 
`playSampleTone` 函数内部声明了局部变量 `const freqToNote = {}`，覆盖了同名的全局函数 `function freqToNote(freq)`，导致调用时出现 "freqToNote is not a function" 错误。

**修复方案**:
将局部变量改名为 `freqToSampleNote`，避免与全局函数冲突。

### 下午会话 (15:15-15:45) - 声调映射功能恢复与E5音量QA

#### 恢复声调映射功能
根据用户之前的设计，恢复了中文声调到音高的映射系统：

| 声调 | 名称 | 音高走向 | 映射区域 |
|------|------|----------|----------|
| 0 | 轻声 | 无音高 | 休止或延续 |
| 1 | 阴平 | 高平 | D4 |
| 2 | 阳平 | 上行 | F4 → B4 |
| 3 | 上声 | 下行-上行 | D5 → F5 |
| 4 | 去声 | 下行 | F5 → B5 |

**实现细节：**
- 添加常用汉字声调映射表 (toneMap)
- 实现 `getCharTone()` 函数检测字符声调
- 实现 `getToneRegion()` 函数映射到音高区域
- 滑音效果：二声、三声、四声使用双音符连奏模拟音高变化
- 轻声：返回休止符 (isRest: true)
- 音符显示添加声调标记（̄ ́ ̌ ̀）和滑音符号（↗）

**代码结构：**
```javascript
// 声调检测
const toneMap = { '一': 1, '二': 4, '你': 3, '我': 3, ... };

// 音高区域映射
const regions = {
  0: { base: 'D4', range: 0, glide: false, rest: true },   // 轻声
  1: { base: 'D4', range: 1, glide: false, rest: false },  // 阴平
  2: { base: 'F4', range: 3, glide: true, rest: false },   // 阳平
  3: { base: 'D5', range: 2, glide: true, rest: false },   // 上声
  4: { base: 'F5', range: 3, glide: true, rest: false }    // 去声
};
```

#### E5音量问题QA
**用户反馈**: E5音量不够大，即使增益加到+10dB (3.16x) 仍感觉和其他音符一样

**浏览器调试结果：**
```
E5: baseGain=3.16, velocity=0.7, final=2.21
D4: baseGain=1.08, velocity=0.7, final=0.76
```

E5的增益已经是D4的**3倍**，但用户感知音量仍相同。

**可能原因分析：**
1. **浏览器音频压缩** - Web Audio API内置动态范围压缩器限制峰值
2. **E5采样本身太弱** - 即使3倍增益也无法弥补原始录音音量差异
3. **心理声学效应** - 659Hz高频听起来自然比294Hz低频弱（等响曲线）
4. **采样文件问题** - E5.wav文件可能有录音问题

## 版本号管理规则

### 版本号格式
**v[MAJOR].[MINOR].[PATCH]**
- MAJOR: 主版本号（重大更新）
- MINOR: 次版本号（功能更新）
- PATCH: 补丁版本号（bug修复）

### 进位规则
- **PATCH ≥ 40 时自动进位**
  - PATCH 重置为 0
  - MINOR + 1
- 示例：v3.3.40 → v3.4.0

### 同步机制
- **文件位置**: `nav-config.js`
- **全局变量**: `const APP_VERSION = 'vX.X.X'`
- **同步方式**: 所有页面引用 `nav-config.js`，通过 `APP_VERSION` 变量显示统一版本号
- **自动更新**: git pre-commit 钩子自动递增版本号
