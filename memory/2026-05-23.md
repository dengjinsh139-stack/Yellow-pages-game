## MIDI Marker 同源导出实现

### 任务
增强 `instrument-language-synth.html` MIDI 导出，让 `characterVoice` 和 `phraseMidi` 事件进入 MIDI 本体作为 Meta Marker/Text，而非仅 JSON sidecar。

### 根因修复：phraseMidi 触发链路
- 之前 `textToEvents()` 第 3380 行跳过 `!category.parsedMidi` 的分类，导致 "别担心" 不匹配 `comfort` 分类时 fallback 为普通 note 拆分
- 修复：改为检测所有有 `keywords` 的分类，无论 `parsedMidi` 是否加载成功
- phraseMidi event 生成与 MIDI 文件加载解耦

### 修改内容
1. **textToEvents()**：去掉 `category.parsedMidi` 限制，改为 `!category.keywords || category.keywords.length === 0` 才跳过
2. **computeMidiTimeline()**：对 `characterVoice` / `phraseMidi` 事件推进 tick 时间线（与实时渲染/WAV 逻辑对齐），生成 `type: 'marker'` 事件
3. **buildMidiFromEvents()**：将 marker 序列化为 MIDI Meta 事件：
   - Meta Marker (0xFF 0x06): `characterVoice:<角色名>` / `phraseMidi:<category>:<keyword>`
   - Meta Text (0xFF 0x01): JSON `{"type":"...","timeMs":...}`
4. **buildMidiSidecarJson()**：markers 数组完整记录两类事件，时间线推进与 MIDI 本体对齐
5. **排序**：同 tick 先 meta（metaMarker > metaText），然后 noteOff，最后 noteOn

- "小牧你不要过去..." → MIDI 二进制含 `characterVoice:小牧`，JSON markers 含 `characterVoice`
- "别担心，小牧现在..." → MIDI 二进制含 `phraseMidi:comfort:别担心` + `characterVoice:小牧`，JSON 含两者

### 技术细节备忘
- `characterVoice` tick 推进：计算 BPM 缩放的 audioDuration/motifDuration + expressionPauseAfterMs - overlapMs
- `phraseMidi` tick 推进：有 parsedMidi 时取 lastNoteEndMs + tailMs(120) + semanticGap，无 parsedMidi 时只加 semanticGap
- sidecar 中 `characterVoice` 时间推进需与 `computeMidiTimeline()` 保持一致
