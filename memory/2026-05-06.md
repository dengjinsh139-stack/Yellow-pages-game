## 2026-05-06 - Expression Segment V1 & DOM Layout Crisis

### 乐器语言合成器 instrument-language-synth.html

**当前版本：v3.22.4**

今日进行了 Expression Segment V1 功能的完整 QA 修复，期间经历了严重的 DOM 布局危机。

#### 问题1：Expression Segment 主链路不工作
- **根因**：`playText()` 中调用 `textToEvents(text)` 后没有调用 `applyExpressionSegments(events, expressionSegments)`
- **修复**：在过滤 null 之前插入 `applyExpressionSegments(events, expressionSegments)`

#### 问题2：字段覆盖破坏原对白
- **根因**：`applyExpressionSegments` 直接写入 `evt.velocityScale`，覆盖了对白模式的力度缩放
- **修复**：所有表达段字段改用 `expression*` 前缀：`expressionTempoScale`、`expressionVelocityScale`、`expressionPauseAfterMs`、`expressionCurveType`、`expressionSegmentId`
- **规则**：新增功能字段必须使用前缀隔离，永远不能覆盖已有字段

#### 问题3：pauseAfterMs 映射错位
- **根因**：段内每个 event 都获得 `pauseAfterMs`，导致「等等」变成两个字各停顿 800ms = 1.6s
- **修复**：`applyExpressionSegments` 中，tempo/velocity/curve 应用到段内所有 event，但 `pauseAfterMs` 只写到最后一个 event
- **结果**：段内逐字速度变化，段末统一停顿

#### 问题4：字符映射错位（标点 pause 映射到后文）
- **根因**：`textToNotes` 中的 `charPos` 计数只统计 `type === 'note'` 的事件，pause 事件被跳过，导致后续 note 的 sourceCharIndex 错位
- **修复**：为所有 event（note + pause + phraseMidi）添加 `sourceCharIndex`，`applyExpressionSegments` 通过 `sourceCharIndex` 查找对应 segment
- **还修复了**：`textToEvents` 递归调用时传递 offset 给子字符串

#### 问题5：ReferenceError - expressionTempo 未定义
- **根因**：`playText` 实时播放循环的 console.log 引用了 `expressionTempo`，但该变量在循环内未定义（只在 `computeEventTiming` 内有）
- **修复**：在 `playText` 循环内重新计算 `expressionTempo` 并应用

#### 问题6：SyntaxError - 重复声明 offset
- **根因**：`function textToNotes(text, offset = 0)` 参数已有 `offset`，函数体内又 `let offset = 0`
- **修复**：删除内部 `let offset = 0`

#### 问题7：pause 显示/日志 undefined
- **根因**：`event.symbol` 为 undefined 时，`[${event.symbol}]` 显示为 `[undefined]`
- **修复**：使用 `event.symbol || event.char || event.punctuation || ''`

### DOM 布局危机（最严重）

`.workbench` 的三栏结构在 v3.21.6 和 v3.21.7 被搞坏，right-panel 嵌套到 center-panel 内部或掉到 body 下。

**错误操作**：通过多次 `edit` 添加/删除 `</div>` 闭合标签来 patch，越修越坏。

**正确恢复流程**（邓锦盛要求执行的）：
1. `git log --oneline` 找到最后一个 workbench 正确的 commit（v3.21.0 / 2dc11c9）
2. `git checkout 2dc11c9 -- sound-effects/instrument-language-synth.html` 恢复整个文件
3. 只补必要的 class 名（left-panel / center-panel）
4. 重新应用已验证的功能修复（detectCharacter / detectSemanticCategories）
5. 添加 LayoutGuard 运行时检查

**LayoutGuard 代码**：
```javascript
const wb = document.querySelector('.workbench');
if (wb.children.length !== 3 || 
    !wb.children[2].classList.contains('right-panel') ||
    document.querySelector('.right-panel').parentElement !== wb) {
    console.error('[LayoutGuard] workbench skeleton broken');
}
```

**教训**：
- DOM 闭合标签错乱时，不要按行号 patch，不要用 Python 脚本插入/删除行
- 应该找到最后一个正确版本，checkout 恢复，然后最小化重放必要修改
- 每次 commit 后应验证 LayoutGuard
